## When to Use
方案选型、平台集成及遗漏推荐复盘；不适用于已经明确限定实现路线的小修复。

## Procedure
1. 分开真实目标与用户给的示例工具，除非明确指定，示例不是路线限制。
2. 检索宿主官方生态目录、GitHub、对应包仓库，覆盖中英文同义词、缩写和旧名，例如「某平台 / 该产品英文名 / 旧产品名」。
3. 读取候选原始文档，核对发布时间、维护归属、会话复用、权限和本机兼容性。
4. 按原生能力或插件、已有桥接、自研排序；引入新宿主前说明原生候选为何不适合。
5. 交付检索来源、候选、排除理由及验证缺口；历史复盘依据原始工具调用而非猜测。

## Pitfalls
- 官网收录不等于官方开发；文档支持不等于本机实测。
- 没检索不能断言不存在；手机网页不等价于客户端入口。
- 兼容性困难时重新检查路线，不要只修补既定复杂方案。
- 用户要求多个工具融合为一个产品时，先设计唯一入口、统一任务状态和审核授权，再选内部通信。把三个界面串通不等于完成整合；一个产品也不必强制一个进程。
## Verification
1. 覆盖官方生态、GitHub、包仓库，缺失则明确披露。
2. 推荐满足真实目标，区分当前会话接入与另起Agent。
